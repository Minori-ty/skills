## 工作流 A：提取设计规范

### 目标

从 Figma 文件拿到可落地的 Token、组件尺寸、页面模式，而不是一份“看起来像”的描述。

### 步骤

1. **解析 URL**

   ```bash
   python scripts/figma_url.py "<figma-url>"
   ```

2. **建会话**

   ```text
   create_session(fileKey, "提取 <项目名> 设计规范")
   ```

3. **列顶层画板**

   对页面节点调 `get_metadata`。只读顶层 frame/component 的 `id`、`name`、`type`、bounds。

   - 如果结果超限，用 `scripts/parse_metadata.py` 解析落盘文件。
   - 记下浅色/暗色画板数量，后面做覆盖检查。

4. **按 frame 读结构**

   对代表性页面逐个调 `get_metadata`：Dashboard、列表、详情、设置、弹窗、空态。

   - 读 `absoluteBoundingBox` 确认画布、留白、内容宽、底部导航。
   - 读组件子节点的尺寸、间距、圆角。

5. **查变量**

   对具体 frame/component 调 `get_variable_defs`。

   - 收集颜色、字体、字号、行高、字重。
   - 记录哪些值没有变量绑定。
   - 变量名和代码 Token 名分开列。

6. **补组件尺寸**

   对关键组件调 `get_metadata`：按钮、输入框、Chip、Card、Nav、Dialog、Sheet、Snackbar。

   - 记录视觉尺寸和点击区。
   - 低于 48dp 的交互控件单独标注。

7. **截图核对**

   对 1–2 个代表页面调 `get_screenshot`，核对层级、留白、阴影、状态。

   - 单帧、绝对路径、合理 scale。
   - 截图只做视觉核对，不量精确值。

8. **写规范**

   按 [输出模板](#设计规范模板) 写；每个结论附来源。

### 交付前检查

- 颜色/字体来自变量或组件节点，不是截图取色
- 圆角/阴影/间距有节点尺寸或变量支撑
- 暗色、空态、错误态、浮层是否覆盖
- 变量缺失、触控不足、对比度不足是否单列
- 没有把推断写成 Figma 事实

## 工作流 B：评审设计稿

### 目标

按严重度输出可执行的修改项，而不是泛泛说“不够统一”。

### 步骤

1. 建会话，读目标 frame 的 metadata 和变量。
2. 读截图，确认实际视觉。
3. 按顺序检查：
   1. 硬规则：多个重色锚点、圆角乱用、阴影过重、颜色做装饰、层级靠边框
   2. Token 漂移：表外颜色/字号/间距；近似值
   3. 对比度：正文 4.5:1，大字号 3:1，控件边界/焦点 3:1
   4. 触控目标：Android 48dp；视觉可小，点击区要补
   5. 状态覆盖：空、加载、错误、校验、删除确认、Undo
   6. 暗色：不是反色；卡片比背景亮；语义色重测
   7. 风格边界：渐变、玻璃、拟物、彩色阴影、emoji 图标、多主色
4. 每条写：严重度 | 问题 | 当前值 | 规范值 | 理由。
5. 对比度必须给实测比值；没有测量工具就写“未测”，不要编。

### 严重度

- **阻断**：违反硬规则、对比度不达标、触控不可用、状态缺失导致流程断
- **重要**：Token 漂移、层级不清、暗色不完整、组件尺寸不符
- **建议**：可优化的节奏、文案、微动效

## 工作流 C：设计转代码

### 目标

把 Figma 节点转成项目现有组件和 Token 的组合，而不是复制一份参考代码。

### 步骤

1. 先加载 `figma-design-to-code` skill。
2. 建会话，选目标区块节点（不要整页）。
3. 调 `get_design_context`，拿到参考结构、样式和提示。
4. 在项目里找现有组件和 Token：
   - 有对应组件就复用
   - 没有就按项目模式新建，并说明复用场景
5. 按项目 Token 重写颜色、字体、间距、圆角、阴影；不要保留 Figma 的原始 hex 作为新 Token。
6. 处理响应式、状态、无障碍：
   - 空/加载/错误
   - 触控 48dp
   - 对比度
   - 暗色
7. 实现后截图或运行项目核对，不只看代码。

### 注意

- `get_design_context` 的输出是参考，不是最终代码。
- 不要因为 Figma 用了某个组件就假设项目也有；先搜项目。
- 设计稿缺的状态，按项目规范补，不要凭空发明交互。
